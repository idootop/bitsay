# design/ —— 碎碎念 Bitsay · UI/UX 设计台

一个**可交互**的设计稿：一个页面里看完整 App 的所有页面、所有组件和桌面小组件。
直接用浏览器打开 `index.html` 即可（**不需要起服务器**，普通 `<script>`，`file://` 就能跑）。

```bash
open design/index.html          # macOS
# 想直接进深色：index.html?dark=1
```

## 设计语言

**押注，而不是每样都做一点。**

之前的版本每样都做了、每样都不敢用力：六个洗淡的粉彩、1.5px 半透明描边、淡奶油色小角色、
一条统计 HUD —— 结果是平庸。现在改成**只押三件事，其余全部安静**：

| 押注 | 做法 |
|---|---|
| **1. 字号量级** | 页面标题 38px / 字重 800 / 字距 -0.035em。这一屏的主角就是标题本身，不靠装饰 |
| **2. 实心剪影角色** | 角色是**实心墨块**（不是描边小可爱），五官用纸色挖出来。实心剪影在任何尺寸都读得出来，描边一缩小就糊 |
| **3. 一个强调色，用在两处** | 朱红 `#E8503A` 只给 **FAB** 和 **勾选圈**。选中 tab 用**实心墨色药丸**，不抢强调色 |

### 配色：整屏只有黑 / 白 / 灰

走了三次弯路才定下来，三次都是**多给了一个色相**：

1. 暖褐底 + 六个粉彩轮转 → 两套气质打架；
2. 冷白底 + 糖果粉彩轮转 → 底色对了，但六个色卡轮流上还是彩虹噪音；
3. 冷白底 + 统一白卡 + 亮黄强调 → 条目干净了，但**亮黄和黑白灰不搭**。

**最终：黑本身就是强调色，不需要第二个色相。**

| 角色 | 值 | 说明 |
|---|---|---|
| 页面底 | `#EDF0F8` | 浅冷灰。比白卡深一档，白卡自己就立起来 |
| 条目 / 纸面 | `#FFFFFF` | **所有条目同一个颜色** |
| 已完成条目 | `#E7EAF2` | 只降一档明度 + 删除线 |
| 正文 | `#191B26` | 略柔和的近黑 —— 纯黑正文读中文会偏硬 |
| 次要 / 更弱 | `#666B80` / `#9CA1B5` | |
| **强调色** | `#000000` | **纯黑**。交互元素一律用它：FAB、勾选圈、选中 tab |
| 强调色（深色模式） | `#FFFFFF` | 暗底上反过来用白，保持"最高对比"这个角色 |

**全屏只有黑 / 白 / 灰三档。** 正文用略柔和的 `#191B26`、交互元素用纯黑 `#000000`，
这个细微差别让按钮比文字"更实" —— 是 Vercel 那套做法。

> **不要在强调色上试第二个色相。** 黄、紫、朱红都试过，用户三次的反馈分别是
> "紫色不太好"、"亮黄和黑白灰不搭"、"太不协调"。一个黑白灰的界面里塞一个彩色，
> 那个颜色会显得是**外来物**，而不是点缀。要活泼靠排版和留白，不靠色相。

其余保持安静：

| 决定 | 为什么 |
|---|---|
| 纸面一律**纯白** `#FFFFFF` | 米白会让彩色卡片发灰 |
| **不用阴影去糊边界** | 分层只靠：色调差 + 发丝线（1px `--c-line`）+ 留白 |
| 圆角统一 20px | 四角不等在大面积色卡上只会读成"没对齐" |
| 按钮是**平的** | FAB 62px 纯色、无阴影 —— 平的就够醒目，加阴影是拿模糊撑场面 |
| **能手绘的地方就手绘** | 空状态标题下面那道朱红下划线（`mascot.squiggle()`），是页面里唯一"不像 UI"的东西 |

深色不是反色：暖纸变暖炭，色卡同色相压暗，**强调色反而提亮**（要在暗底上跳出来）。
因为角色是"实心 ink + 纸色五官"，深浅色切换时它会**自动反相**，不用单独画一套。

## 生命力：生长，不是画一个吉祥物

设计师原话是"像游戏一样生动，像植物生长，像童话故事"，同时明确否掉"幼稚的便签卡通形象"。
这两句话并不矛盾 —— 它要的是**生命力**，而生命力可以来自形态、光线、动势，不必来自角色。

所以生命力分成四层，没有一层是"画个小人"：

| 层 | 做法 |
|---|---|
| **光** | 页面底是**一段光**不是一块死灰：顶部天光（冷白）→ 中段纸面 → 底部**极淡苔绿**。苔绿淡到几乎看不出色相，只提供"上面是天、下面是土"的生长感 |
| **形** | 卡片圆角是**叶形**：一对对角饱满、另一对收敛（`26px 16px 26px 16px`）。四角全一样是工业品，对角有差别才是长出来的 —— 注意这是**有规律**的不对称，乱设会读成没对齐 |
| **势** | 新增的条目**自己冒出来**（`sprout`：从下方 14px 升起 + 微缩 + 淡入，整列错开 26ms 依次发芽）；勾掉待办时完成圈**轻轻落定**；FAB 以 5.6s 周期呼吸 3.5% |
| **字** | 大标题用**衬线**（宋体/Noto Serif CJK）。绘本都是这样排的 —— 童话感来自字形，不来自装饰 |

### 空状态怎么在设计台里同时展示"有数据"和"没数据"

设计台是共享一份数据的，所以空状态平时看不到。做法是**渲染一帧后把视图冻住**：

```js
const real = S.state.items;
S.state.items = [];            // 临时清空
const inst = mount(host);      // 这一帧渲染出空状态
inst.unmount();                // 立刻退订，冻住
S.state.items = real;          // 还原数据，其它视图照常有内容
```

**不需要给页面加任何"测试专用开关"**。唯一的前提是 `unmount` 要真的干净 ——
`widget.mount` 原来只退订、没断开 `ResizeObserver`，尺寸回调会再触发一次 `render`，
把它从"冻住"变成"用新数据重绘"。这个泄漏已经修掉（`unmount` 现在同时 `disconnect`）。

另外 `widget.render()` 加了**渲染签名**：内容（kind / 顶栏是否显示 / 可见行 / 行内容）没变就不重绘。
不这么做的话，`ResizeObserver` 挂载后的那次回调会把 DOM 整体换掉，
空状态里嫩芽的绘制动画被打回起点 —— 看起来就是"嫩芽没画出来"。

### 空状态的那株嫩芽是【幼苗】，不是藤蔓

这两个画法差很多，别搞混：

| | 长相 |
|---|---|
| ❌ 藤蔓 | 两片叶**错开**长在茎的不同高度上 —— 第一版画成了这样，读起来像爬藤 |
| ✅ 幼苗 | 茎从底部直直长上来，**两片叶在顶端同一个节点向左右张开** |

节点在 `(32,36)`，叶尖 `(13,16)` / `(51,16)`，茎从 `(32,84)` 长到节点。
动画顺序也跟着改：茎先长 → 两片顶叶**几乎同时**张开（`.42s` / `.46s`），
而不是之前那样一前一后抽。

### 空状态的那株嫩芽

空状态里有一株**植物线描**（`js/sprout.js`）：只有线条，没有五官、没有身体。
进场用 `stroke-dashoffset` 让它**自己长出来**：茎 0s → 左叶 .42s → 右叶 .66s；
长完停在原地，整体再以 7s 周期极缓地摆 1.4°（像有风）。**不循环画线** —— 循环会变成"在闪"，不是"在长"。

配色上用唯一的绿 `--c-leaf: #8CA487`。**它只是植物的颜色，不是 UI 强调色** ——
强调色仍然是纯黑，只给 FAB 和勾选。

**小组件的空状态用的是同一株嫩芽**，按尺寸给不同大小：2×5 → 74px、2×3 → 60px、2×2 → 38px。
2×2 里**不隐藏** —— 藏起来会读成"这个组件坏了"，缩小反而像刚发芽。

> **动画的基态必须等于"最终状态"。** 嫩芽最初写的是
> `stroke-dashoffset: var(--len)` + `forwards`，也就是"基态 = 没画"。
> 这很脆：动画一旦没跑（时序、离屏、系统降级），嫩芽就永远隐形，但布局位置还占着 ——
> 看起来像组件坏了。现在改成**基态 = 已画完**（`dashoffset: 0`），
> 由 `@keyframes` 的 `from` 提供"没画"那一端，`fill-mode: backwards` 保证延迟期间是空的。

> **为什么这次不算"又加了个角色"**：卡通角色是**拟人的物件**（便签精灵、仓鼠），幼稚且抢戏；
> 植物线描是**绘本里的静物**，安静、不参与交互、不进常驻界面。区别在"有没有人格"。

## 只有一份样式

**没有多套主题 / 多个版本**，就是这个 App 的样子。要调观感，按下面这张表找地方：

| 想改什么 | 改哪个文件 |
|---|---|
| **颜色、圆角、描边、间距节奏、字号、点阵强度** | `css/tokens.css` ← 优先改这里 |
| **某一个页面**的样式 | `css/pages/<页面>.css` 顶部的「本页可调参数」 |
| 卡片 / tab / FAB 等跨页面组件 | `css/components.css`（谨慎，全站都会变） |
| 深色模式 | `css/dark.css`（只做 token 替换，页面样式不用动） |
| 图标 | `js/icons.js` |
| 数据规则（排序 / 搜索 / 新增 / 删除） | `js/store.js` |
| 某个页面的结构与交互 | `js/pages/<页面>.js` |
| 页面清单 | `js/app.js` |

页面与它们的 `.css` / `.js` 一一对应：
`list`（笔记 + 待办列表、多选）、`editor`、`search`、`settings`、`widget`、`homescreen`（演示用的真实桌面外壳，不属于 App）。

### 「本页可调参数」怎么用

每个 `css/pages/*.css` 顶部都留了这样一段，改它只影响这一页：

```css
/* ---------- 本页可调参数（只影响列表页，覆盖 tokens.css） ---------- */
.list-page{
  --list-pad-x: var(--pad-page);   /* 左右留白，默认 18px */
  --list-gap: var(--gap-list);     /* 条目间距 */
  --card-pad-y: 14px;              /* 卡片上下内边距 */
  --card-pad-x: 16px;
}
```

## 约定（务必遵守）

1. **页面样式里不许写死颜色**，只能引用 `var(--c-*)`。写死了，切深色就会漏。
2. **卡片只有一处实现**：`js/ui.js` 的 `BitSay.ui.card()`。首页和搜索页都调它 ——
   和 Android 侧共用 `ui/components/ItemList.kt` 是同一个理由：两套实现一定会漂移。
3. **颜色只走 token**：`css/tokens.css` 定义，`css/dark.css` 替换，页面 CSS 一行都不用改。
4. 演示台外壳（`.shell` / `.panel` / `.knob`）**不吃 App 的 token**，用的是 `--sh-*`，
   否则切深色连演示台一起变，就看不清 App 本身了。

## 加一个新页面

1. `css/pages/<name>.css`（顶部留「本页可调参数」区块）；
2. `js/pages/<name>.js`，导出 `mount(host, opts)`；
3. `index.html` 里加 `<link>` 和 `<script>`；
4. `js/app.js` 里挂到演示台路由和总览网格。

## 应用图标（`js/appicon.js`）

概念是**空状态那株嫩芽** —— 它在页面里已经建立了"生长"的语言，图标就是把它压成一个能被认出来的记号。

画布按 Android 自适应图标规范：**108×108，可见区中间 72×72，安全区是以 (54,54) 为心、半径 33 的圆**。
每个方案的最远点都核过 **≤32.6**，所以圆形 / 圆角方 / 方形三种裁切都不会切到主体。

看图标**一定要看 48px 和 24px**，母版好看不算数 —— 设计台里每一行都给了这两个真实尺寸。

### 底色定死墨黑

**所有方案一律墨底（`INK #17140F`）**。这一条是被用户否掉两轮之后定下来的：

- 纸色底（`SAND #F2EDE4`）——「纸色背景不好看」，全部作废；
- 深绿底 —— 绿成了品牌色，和 App 内「绿只给植物」的规则打架，删。

由此推出一条硬规则：**任何新方案先过"放在墨底上还看不看得见"这一关。**
石缝探芽原来用墨色石头配纸底，换成墨底后石头直接消失了 —— 必须改成石灰色（`STONE #55534C`）、
裂缝改用更暗的墨线压出来，才读得出是"裂开的石"而不是"一丘土"。

### 定稿：`C5` 破土

**2026-10 用户敲定。** 土被顶开成左右两半、中间一道 V 形缝，芽从缝里长出来 ——
七个方案里唯一"有动作"的一版，讲的不是"站在土上"而是"从土里挣出来"。

已落到 Android 资源（改 `appicon.js` 就必须同步改这些）：

| 文件 | 内容 |
|---|---|
| `drawable/ic_launcher_background.xml` | 纯墨底 `#17140F`，什么都没有 |
| `drawable/ic_launcher_foreground.xml` | 两瓣土 `#2C4A35` + 茎/叶 `#7FC98F` |
| `drawable/ic_launcher_monochrome.xml` | 主题图标层，**土合并回一整丘**（见下） |
| `drawable/ic_widget_open_app.xml` | 同一份几何缩 0.38 到 24dp，**单色** `#3D3A38` |

`ic_widget_open_app.xml` 是**看起来最不像图标、却最容易被忘掉**的那一个：widget 顶栏
「进入 App」按钮原来画的是便签+对勾，是旧黄色图标那一套。品牌换了，它必须跟着换，
否则桌面上是芽、点进 App 的按钮还是便签。

### 这一族踩过的坑

- 土壤画成**一丘收在安全区内的土**，不是一条通到底的横带 —— 横带被圆形遮罩切完只剩一弯月牙，很怪。
- 线描版的土**必须闭合**（穹顶 + `Z`），茎从穹顶顶端起笔。开口的土配一根插进去的茎，会读成一只杯子。
- 破土版的缝要做成 **V 形（上宽下窄）**。直槽读不出"被顶开"，只像渲染坏了。
- 石缝版用**先画芽、后盖石头**的次序，露出来的就只有脑袋。
- 石头必须是**有棱角的多面体**。圆丘一定会被读成土，和 C 族重复。
- 几何版的两片叶用**倾斜椭圆**。正圆会读成棒棒糖，椭圆才是叶。

## 界面图标（`js/icons.js`）

- 齿轮是 **6 齿**，不是 8 齿。8 齿在 21dp 下齿间糊成一片，轮廓不再读得出是齿轮；
  6 齿留得住齿形。**别退回「圆圈 + 放射线」** —— 那是太阳/亮度图标。
- 「显示语言」必须画成**地球**：圆 + 赤道 + 经线椭圆。曾经画成两条横线，那是"行距"图标。
- 「主题」的右半实心路径**必须闭合**（`…a8.6 8.6 0 010 17.2z`）。少了结尾的 `z`，描出来是个逗号。

## 顶部天光

`.app-root` 的 `radial-gradient` 天光走 `--c-glow` 令牌，**暗色下 `--c-glow-d` 是透明的**。
近黑的底上盖一层 92% 白会把整屏洗成灰 —— 暗色截图里一眼就能看出来。
- **定稿的 V 形缝在缩小到 24dp 时会消失。** 5 单位的缝缩完只剩 1.9，读起来不像"缝"
  而像渲染毛刺 —— 所以 `ic_launcher_monochrome` 和 `ic_widget_open_app` 都把两瓣土
  **合并回一整丘**。彩色前景保留缝，单色场景不保留。

## 图标字形要按 viewBox 的留白放大

`--w-tick-glyph` 给的是 **svg 盒子尺寸**，不等于画出来的图形尺寸。
`todoOpen` 的圆是 `r=8.6`，在 24 的 viewBox 里只占 72%：

```
盒子 16px → 圆只有 11.5px   ← 最初的值，看起来就是"浮着一个小点"
盒子 26px → 圆 18.8px       ← 现在的值
```

所以勾选圈看起来"和文字离得远、前面很空"，根因不是 padding 写错，而是**图形本身太小**。
放大字形之后，圈↔文字从 16px 收到 10.6px，左侧也不再空 —— **一行 CSS 都没动 padding**。

配套的两处：

* 描边要**归一化**：App 里的圈是 23px + 1.5px 边框，小组件是 26px 盒子，
  所以 `stroke-width` 用 1.45（渲染成 ~1.57px）才对得上；用 2 会明显重一档。
* 勾选圈的颜色统一走 `--c-ink-3`（原来 App 用 `rgba(34,29,24,.22)`≈#D5D3CF、
  小组件用 `--c-ink-2`，两边深浅对不上）。`.pick`（多选圈）一并改了。

> 背景不同会有对比错觉：同一个 #9CA1B5，放在白卡上比放在浅灰行上显得淡。
> 这是正常的，**不要去"补"它**，否则两边又会不一致。
